    XMPP¶

    created: 2026.5.22

    개념¶

    XMPP(Extensible Messaging and Presence Protocol) - XML 스트림을 주고받아 실시간 메시징, 프레즌스(접속 상태)를 처리하는 개방형 표준 프로토콜 - 확장 가능

    배경¶

    • 1999년 Jeremie Miller가 개발한 Jabber라는 이름으로 시작
    • 당시 메신저(MSN, ICQ, AIM)들은 서로 폐쇄적이고 호환이 안됨 -> 이메일처럼 어느 서버를 쓰든 서로 대화할 수 있게 하자
    • 2004년 IETF 표준화
    • 이메일을 닮은 탈중앙 메시지 -> 이메일과 유사한 주소 체계(user@domain) - 누구@어느서버/어느기기

    연결 생명주기¶

    1. TCP 연결: 클라이언트 -> 서버 5222 포트로 소켓 연결
    2. 스트림 열기: <stream:stream> XML 여는 태그를 서로 보냄
    3. STARTTLS: 평문 연결을 TLS로 암호화 업그레이드
    4. SASL 인증: 아이디/비번 등으로 로그인
    5. 리소스 바인딩: full JID 확정(user@domain/resource)
    6. 세션 시작 -> 통신: stanza를 자유롭게 주고받음
    7. 스트림 닫기: </stream:stream>으로 종료

    연결을 한번 열어두고 계속 유지(long-lived) - 열린 통로로 메시지가 양방향으로 흐름

    XML 스트림¶

    • XMPP 세션 하나가 거대한 XML 문서 
      <!-- 클라이언트가 보냄: 문서 시작 -->
<stream:stream to="example.com" xmlns="jabber:client">
    <!-- 세션 동안 이 안에 stanza들이 계속 들어감 -->
    <presence/>
    <message to="bob@example.com"><body>안녕</body></message>
    <iq type="get">...</iq>
<!-- 종료 시: 문서 닫기 -->
</stream:stream>
    • <stream:stream> ... </stream:stream> = 한 세션
    • 그 사이 XML 조각 하나하나가 stanza

    Stanza¶

    • 주고 받는 XML 단위
    • <message> - 메시지 전송(단방향), fire-and-forget 
      <message from="ax@ex.com" to="bx@ex.com" type="chat">
    <body>점심 뭐 먹지?</body>
</message>
      • type 속성으로 종류 구분
      • chat(1:1), groupchat(단체방), headline(공지/알림), normal, error
    • <presence> - 접속 상태 
      <presence>
    <show>away</show>
    <status>회의중</status> <!-- 상태 메시지 -->
</presence>
      • show: away, dnd(방해금지), xa(장기 부재), chat(대화가능)
      • presence는 구독(subscription) 관계가 있어야 수신 가능
    • <iq> - Info/Query, 요청-응답(get/set/result/error) 
      <!-- 요청: 친구 목록 -->
<iq type="get" id="r1"><query xmlns="jabber:iq:roster"/></iq>
<iq type="result" id="r1"><query xmlns="jabber:iq:roster">
    <item jid="bx@ex.com" name="bx"/>
</query>
</iq>

    Roster & Subscription¶

    • 로스터: 서버에 저장되는 내 연락처 목록
    • 친구 추가: presence 구독 요청을 보내고 상대가 수락
    • 수락하면 서로의 presence를 볼 수 있음

    확장성¶

    • XEP(XMPP Extension Protocol)로 추가

    아키텍처¶

    • C2S (Client-to-Server): 클라이언트는 자기 서버에만 붙음
    • S2S (Server-to-Server / 페더레이션): 서버끼리 연결되어 다른 도메인 사용자와도 대화 가능(이메일 원리)
    • 탈중앙적 - 하나의 서버에 종속되지 않음

      페더레이션: 서로 독립적으로 운영되는 여러 서버가 연결되어, 다른 서버에 있는 사용자끼리도 대화할 수 있는 구조

    XMPP vs 다른 프로토콜¶

    XMPP HTTP 폴링 MQTT
    실시간성 o (상시 연결) x (반복 요청) o (상시 연결)
    표준화 IETF - o
    페더레이션 서버 간 연결 x x
    용도 메신저/프레즌스 일반 웹 IoT 센서

    정리¶

    JID 주소 잡고 → XML 스트림 열고 → TLS+인증+바인딩 거쳐 → message/presence/iq stanza를 주고받는다.

    부족한 기능은 XEP로 확장.
